# 对话式学习计划 V1：本地提交交接说明

> 本文记录截至本地基线提交时已经实现并验证的能力，以及下一轮尚未实现的产品改造。后续开发以本文的“待开发”部分为准，不能把其中内容当成已上线能力。

## 1. 当前已实现的基线

### 1.1 对话草案与正式计划分离

- `MasterRouter` 保持原有意图分类；仅当已经判定为 `study_plan` 时，才将原始聊天文本传入计划服务。
- 计划服务可解析自然语言中的教材、章节、天数、每日时长和用户指定重点，按知识图谱校验后生成带 TTL 的 `PlanDraft`。
- 草案与正式日历计划项分离。草案不会自动写入、改写或完成日历任务。
- 同一聊天会话中，后续计划意见可带上一份草案 ID 生成新的子草案；已采纳任务不会被聊天静默覆盖。
- 现有计划页可通过 `plan_draft_id` 加载草案，并通过既有采纳流程写入正式计划项。

### 1.2 正式计划项的范围与学习启动

- 正式计划项保存 `learning_scope`，其中可含教材、文档、章节、章节标题及 KG 知识点 ID。
- 从正式计划项启动学习时，Router 将 scope 交给既有学习编排器和 planner；普通“学习第三章”仍走原有 `learning` 路径，不读取计划项。
- planner 会按 `document_id`、章节和 KG ID 限制资料；范围失效时返回明确错误，不回退到全局模糊检索。
- `continue_lesson` 计划项恢复当前讲解节点，不会在启动时推进到下一节或自动完成课程。
- 课程 session 完成与计划项完成分离；计划项仍须用户显式完成。

### 1.3 已知当前缺陷（下一轮必须修正）

- 定制草案的任务拆分仍可能把同一目标机械生成为“目标（1/5）…目标（5/5）”，每项范围和理由相同。
- 当前计划生成还没有“章节学习 → 复习 → 练习”的内容结构。
- 计划中的 `review_*`、`practice` 点击后仍会按主题启动针对性学习；尚未正确接入复习和阶段卷执行语义。
- 阶段卷后端已可生成、提交、判分并回写掌握度，但聊天页面目前只读展示题目，未接入作答/提交 UI。

## 2. 已核实可复用的既有能力

| 能力 | 真实入口 | 当前可用程度 | 本轮使用方式 |
| --- | --- | --- | --- |
| 章节/知识点学习 | `MasterRouter._start_learning` → orchestrator/planner | 可用，支持 `learning_scope` | 学习任务直接复用。 |
| 基于薄弱点/掌握度的复习推荐 | `study_plan.py` 的 weakness/mastery recommendation + 针对性学习启动 | 有推荐依据，但没有独立复习执行模式 | 复习任务传入原章节 scope，并复用既有针对性学习路径。 |
| 阶段卷生成 | `generate_stage_exam`，学习 session 完成时由 orchestrator 调用 | 可生成；每个 outline 小节默认 1 题 | 基础练习复用。 |
| 阶段卷提交与掌握度回写 | `POST /api/learning/session/{session_id}/stage-exam/submit` | 后端可用 | 计划练习只做任务→既有链路接线，不重写出题、判卷或回写。 |

阶段卷不具备可靠的“高难题筛选”：当前只有 `questions_per_section=1..3`，题目排序依据是范围匹配/链接质量/权威度，不是难度。不得将“多出题”伪称为“提高题”。

## 3. 下一轮产品规则（待开发）

### 3.1 计划生成的三种输入模式

1. **指定单章**
   - 一章是一条有明确范围的学习任务，不是一知识点一条日程。
   - 范围展示为：教材、章节、该章实际 KG 知识点名称。
   - 默认排两天：
     - 第一天：学习本章 + 基础练习；
     - 第二天：复习本章 + 提高练习。

2. **指定整本书**
   - 按章节顺序滚动，而不是把全书知识点平铺或把整本书排在同一天。
   - 第一天：第 1 章学习 + 基础练习。
   - 第 N 天：第 N 章学习 + 基础练习，同时安排第 N-1 章复习 + 提高练习。
   - 最后有全书总复习和总练习。
   - 每个任务都必须说明具体教材、章节、知识点范围；不得只有“复习”或“练习”。

3. **未指定内容：只说“帮我制定学习计划”**
   - 优先使用真实信号：未完成/中断 session、近期学习章节、阶段卷与答题记录、KG 掌握度、已记录薄弱点、画像目标和节奏偏好、与近期学习有关联的章节。
   - 用户明确指定范围时，该范围是硬约束；画像只影响优先级、节奏及学习/复习/练习比例，不能擅自换教材或章节。
   - 如果没有足以决定学习范围的知识点掌握度、错题、薄弱点或近期学习资料，**不要生成通用模板**。由当前聊天中的模型自然追问用户想学哪本教材、哪个章节或哪个薄弱点；用户回答后再生成草案。
   - 推荐任务必须说明真实依据，例如“上次学习停在第 2 章”或“该知识点阶段卷掌握度偏低”；无证据不得宣称系统识别了薄弱点。

### 3.2 学习、复习、练习的定义

- **学习本章**：已有精确章节/知识点 `learning_scope` 的学习链路。
- **基础练习**：学习本章后复用该 session 的阶段卷；每小节 1 题，覆盖本章范围。
- **复习本章**：使用同一章节/知识点范围启动已有针对性学习，并让既有掌握度/薄弱点数据影响复习内容；不新造复习引擎。
- **提高练习**：不承诺“高难题”。以基础练习结果或 KG 掌握度筛出薄弱知识点，建立该定向范围的学习 session，再复用阶段卷作为二次测验。

## 4. 约束与非目标

- 不改变 `MasterRouter` 的分类规则或其他 intent 的调度。
- 不新增计划页面或填写表单。
- 本轮先不改前端：不实现聊天草案“全部采纳/忽略”、不改计划页视觉、不实现阶段卷聊天作答 UI。
- 不修改阶段卷内部题库、出题、判卷、掌握度回写或难度筛选；只补计划任务到既有链路的接线。
- 不修改无关 PPT、Direct QA、文献、知识图谱展示接口。
- 普通“学习第三章”继续直接进入学习路径，不能被计划逻辑劫持。
- 不得让 session 完成自动完成正式计划项。

## 5. 建议开发顺序

1. **事实范围数据补齐**：从现有章节/KG provider 取得章节真实知识点名称，供草案显示和任务范围使用；没有名称不能用假编号代替。
2. **生成器重构**：替换机械编号拆分，按单章/整书/未指定内容三种输入模式生成带范围、依据、日期和任务语义的草案。
3. **未指定内容的追问分支**：只有在画像和学习记录不足以确定范围时，返回聊天澄清而非草案；保留上下文以消费用户下一句回答。
4. **正式任务数据契约**：为学习、基础练习、复习、提高练习保存统一的范围、前置任务/关联 session 和练习层级；保持旧计划项兼容。
5. **执行路由接线**：学习→已有 scope 学习；复习→已有定向学习；基础练习→对应学习 session 阶段卷；提高练习→薄弱范围 session 的阶段卷。不得把 `practice` 静默路由成普通学习。
6. **后端回归测试**：覆盖三种生成模式、无数据追问、范围展示、全书滚动顺序、任务→既有链路映射、错误范围不回退、课程与计划状态分离。
7. **独立运行时验收**：以真实数据验证单章和整书草案均不含重复编号任务；验证每一项的教材/章节/知识点范围和执行入口一致。
8. **后续前端轮次（本轮不做）**：聊天草案的采纳/忽略/全部采纳，阶段卷可作答提交，以及计划页展示任务依赖与练习状态。
